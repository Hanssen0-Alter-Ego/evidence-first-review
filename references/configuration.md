# Deployment configuration

Resolve placeholders through the owner's authorized setup. Missing eligibility or write identity means no external write. Configuration values do not themselves prove authorization; retain a verifiable authorization reference in the deployment, outside this portable package. Use authenticated account IDs, not display names or email text, to establish identity.

The example file [config.example.json](../config.example.json) is intentionally non-operational. Replace repository, owner destination, bot identity, cutoffs, exclusions, and allowed operations explicitly. An email address, if needed by an email trigger, belongs only in private deployment configuration. Do not ship someone's actual configuration with this skill.

`publish.enabled=false` permits only read-only review. Enabling publishing additionally requires authorization for the exact audience and operation. Replace the example attribution placeholder with an honest agent/publisher identity. For example, a dot deployment may use `Generated by ChatGPT · Alter Ego`; that is an optional deployment choice, not a required identity or dependency. Do not imply an affiliation or identity the publisher does not have.

Support access through the tools actually available. No dependency on a particular assistant product, scheduler, secret store, or command-line tool is required. Keep tokens in the platform's credential mechanism, never in configuration, checkpoints, prompts, or comments.
